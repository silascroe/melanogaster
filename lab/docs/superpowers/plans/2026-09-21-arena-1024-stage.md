# Arena 1,024-Node Stage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make a real, deterministic 1,024-node connectome-backed arena stage runnable through the Python API, browser lab, and Godot live loop, with compact evidence from the local FlyEM release.

**Architecture:** Extend the existing exact multi-hop sensory-to-descending expansion rather than inventing a second graph builder. Keep the 54-node compatibility stage and 250-node unified stage as controls, add 1,024 as the first serious scale target, and fail if the selected graph does not contain exactly the requested number of unique official body IDs. Keep Python/NumPy as the neural runtime for this slice; measure it before choosing a compiled replacement.

**Tech Stack:** Python 3.12, NumPy, PyArrow, pytest, browser JavaScript, Godot 4 GDScript.

**Spec:** User-approved bounded design recorded in this plan; no separate architectural spec is needed because this changes the existing arena stage flow without changing the neural backend or API schema.

## Global Constraints

- Never edit `data/original-data/`; original and working release files must remain byte-identical.
- Use unique body IDs and actual induced connectome edges; never pad a stage with duplicate or unrelated fake nodes.
- Preserve the existing one-step delay, native-sign convention, default LIF behavior, and stage-54 control behavior.
- Keep the public API default at stage 54 for compatibility; the browser and Godot live lab may default to 1,024 explicitly.
- Do not commit Feather files, backups, `.venv/`, caches, or bulky timestep traces.
- Write only compact JSON/Markdown acceptance evidence under `outputs/diagnostics/arena-1024/`.

## Review Focus

- A request for 1,024 must select exactly 1,024 unique official body IDs, not merely accept the requested number in configuration — covered by the real acceptance diagnostic and its summary assertions.
- Cross-channel deduplication must remain deterministic and preserve both sensory routes and descending output populations — covered by stage metadata assertions and the real run.
- Invalid stage values must retain a clear validation error while 54/100/250 remain accepted — covered by arena configuration tests.
- Browser and Godot must request the same 1,024 stage rather than silently remaining on 250 — covered by frontend contract tests and script inspection.
- The first build may be slow while scanning the large weights table, but cached replay and live session steps must complete and remain deterministic — covered by acceptance timing/digest evidence.
